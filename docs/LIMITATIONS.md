# 制限事項

ここでの「未検証」は、実装時点の開発環境で実配信へ接続して成功を確認していないことを意味します。ローカルの単体テストと、ffmpeg が使える場合のファイル確定テストは別です。

## 実配信

| 機能 | 状態 |
| --- | --- |
| TikTok の配信有無（room API。1人ずつ、1.5秒間隔。403・429・5xx・空応答は5分休止） | 実装済み。実配信は未検証 |
| TikTok 録画 Streamlink 8.6.3 | 実装済み。公開配信以外は失敗として記録。実配信は未検証 |
| TikTok 録画 yt-dlp 2026.10.26 | フォールバックとして実装。2026年10月時点で HLS の 404/503 が報告されており、安定手段ではない |
| TikTok 録画 TikTokLive + FFmpeg | ルーム情報に含まれる HTTPS の配信 URL だけをコピー。署名サービスが必要。実配信は未検証 |
| TikTok コメント | `CommentEvent` の実在フィールドだけを保存。Euler Stream への署名要求が起きる。実配信は未検証 |
| ツイキャス配信状態とコメント | 公式 API。認証情報が必要。実配信は未検証 |
| ツイキャス録画 | 公式 `hls_url` を優先し、無い公開配信だけ Streamlink の HLS。WebSocket 低遅延配信は使わない。実配信は未検証 |

## 取得しないもの

- 合言葉配信、メンバーシップ配信、年齢制限、非公開配信を回避する処理
- クッキー、セッション、CAPTCHA 解決、署名の自前生成
- ブラウザ内の動画再生、Range によるシーク、ライブプレビュー、HLS 再配信

ダウンロードはファイル全体を `Content-Disposition: attachment` で返します。`Accept-Ranges` は `none` です。

## TikTok の署名サービス

コメント接続と TikTokLive 経由の録画は、ライブラリの既定で Euler Stream に署名を依頼します。Community 枠の目安は 1日 1,500 リクエスト、同時 25 WebSocket です。費用と上限は Euler Stream の公開料金に従い、このアプリは課金処理を持ちません。API キーは `SIGN_API_KEY` にだけ置きます。

TikTokLive 7.0.1 のライセンスは Modified AGPL-3.0 です。個人の自宅サーバでこのプロセスを動かす前提で依存関係に含めています。

`CommentEvent.common.create_time` は、値が存在するときだけ使い、桁数から秒、ミリ秒、マイクロ秒を区別します。フィールドが無いコメントの投稿時刻は NULL です。

## ツイキャス

コメント API は1回50件まで、レートの目安は 60 リクエスト/60秒です。アプリは毎分50リクエストを上限に待ちます。削除済みコメントや、接続前で取り切れなかったコメントは保存できません。`slice_id` は公式説明どおり「そのコメントID以降」を追加取得に使います。解釈が変わった場合は重複排除で二重保存を避け、取りこぼしは欠損として残します。

## コメントの完全性

配信中の全コメント取得は保証しません。フィルタされたコメント、削除されたコメント、WebSocket 接続前のコメントは欠けることがあります。欠損は `collection_gaps` に理由付きで残し、取得済みの行は消しません。

## 音声字幕と統合 ASS

- `transcriber` は NVIDIA GPU を使う前提です。GPU ランタイムが無い環境では起動しません。文字起こしは1件ずつで、配信中の録画は対象にしません。推論は温度 0、無音除去ありで、前の区間の本文を次の条件にしません
- 圧縮率が 2.4 を超える区間、平均対数確率が -1.0 未満の区間、記号だけの本文、無音の定型句そのもの、同じ節が3回以上続くもの、12文字以上で直前と同じ本文は字幕に残しません
- 字幕の文章は Whisper のセグメントのままです。語の時刻は、その区間の内側に収まるときだけ開始と終了に使います
- 次の音声字幕が 0.4 秒以内に続く区間は、ASS でもその終了まで出します。間が空くときだけ、表示を最短 2.5 秒、最長 10 秒に切ります
- 統合 ASS は1トラックです。再生中に音声とコメントの片方だけをファイル内で消すことはできません

## 運用上の上限

- ワーカーは1プロセスです
- 同時録画の既定は3本です
- コメントの手動書き出しは1回あたり最大10万件です
- 同一本文の連投は、投稿時刻または受信秒が違えば別コメントとして残します
- プラットフォームコメントIDがある場合、同じ配信セッションでは先に保存した1件を残します

## 検証の切り分け

この作業環境で確認できたもの:

- ネットワークを使わない単体テスト
- ffmpeg がある場合の短い MPEG-TS の MP4 化
- 一時的な PostgreSQL 16 に対する初期マイグレーションと、モックの配信検知で録画ジョブとコメントジョブが独立に作られること
- `docker compose config` と `live-recorder:local` イメージのビルド

確認していないもの:

- 実在の TikTok LIVE とツイキャスへの接続
- 署名サービスやツイキャス開発者トークンを使ったコメント収集

データベース試験は `LIVE_RECORDER_TEST_DATABASE_URL` があるときだけ実行します。失敗した項目を成功には数えません。
