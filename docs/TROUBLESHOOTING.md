# 障害時の確認

## 管理画面が開かない

`app` のログと `docker compose ps` を見ます。`/healthz` が 503 のときは PostgreSQL に接続できていません。`SESSION_SECRET` が短い、または例示の値のままだとプロセスは起動時に止まります。

## ワーカーが再起動を繰り返す

ログに「別のワーカーが稼働中です」と出る場合、別の worker コンテナがロックを持っています。プロジェクト内の worker は1つにしてください。前回のプロセスが落ちた直後は、ロック解放を最大30秒待ちます。

## 配信者がエラーのまま

TikTok の `is_live` がタイムアウトまたは例外になると `ERROR` です。これはオフラインではありません。監視は他の配信者を続けます。失敗した配信者だけ指数バックオフで間隔を空けます。

ツイキャスで `credentials_missing` または `auth_401` のときは Client ID / Secret を確認します。`user_not_found` は screen_id の誤りです。配信していないユーザーは `OFFLINE` です。

## 録画が始まらない

- 録画スイッチと全体の同時録画上限
- 空き容量が最低値を下回っていないか
- 合言葉、メンバーシップ、年齢制限。これらは別エンジンへ切り替えません
- Streamlink が「The stream is inaccessible」を返したとき。公開配信以外は失敗として記録し、回避のためのクッキー注入は行いません

エンジンの最終失敗理由は「システム」画面に出ます。抽出失敗のときだけ、設定した順序で次のエンジンを試します。データを受信したあとの切断は、同じエンジンで再接続し、欠損区間を残します。

## コメントだけ失敗する

TikTok のコメントは Euler Stream への署名が必要です。`SIGN_API_KEY` が空でもライブラリは接続を試みますが、制限や失敗でコメントジョブが `FAILED` や `PARTIAL` になることがあります。録画ジョブは止まりません。

ツイキャスのコメントは movie ID が取れてから、最大50件ずつ、全体でおおよそ毎分50リクエスト以内に取得します。収集開始前のコメントは「欠損」として残すことがあります。

## ファイルが再生できない

履歴の検証が `invalid` または `partial` のファイルは、MP4 への詰め直しに失敗したか、途中で切れています。ダウンロードできる形式のまま残してあります。画面では再生しません。

## 容量

自動削除がオフのときはファイルを消しません。設定で有効にし、保存期限が1日以上のときだけ、期限を過ぎた確定ファイルを削除します。コメント期限を設定すると、期限を過ぎたコメントと自動書き出し JSONL を削除します。手動エクスポートは保存しません。

## ログに秘密が出る

`sign`、`token`、Bearer、URL はマスクします。それでも気になる値があればログレベルを `INFO` のままにし、`DEBUG` へ上げた状態を長時間残さないでください。
