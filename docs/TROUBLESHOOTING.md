# 障害時の確認

## 管理画面が開かない

`app` のログと `docker compose ps` を見ます。`/healthz` が 503 のときは PostgreSQL に接続できていません。`SESSION_SECRET` が短い、または例示の値のままだとプロセスは起動時に止まります。

## transcriber が起動しない

`transcriber` が次のエラーで落ち、同じ `docker compose up` の `app` も中断されることがあります。

```text
failed to fulfil mount request: open /usr/lib/wsl/drivers/nv_dispi.inf_amd64_.../NvFBC.dll: no such file or directory
```

WSL 上の Docker は GPU を渡すとき、`/var/run/cdi/nvidia.yaml` に書かれた Windows ドライバのパスをマウントします。ドライバを更新すると、このディレクトリ名のハッシュが変わります。Windows の再起動で WSL が起動し直されると、有効になっている `nvidia-cdi-refresh.service` が仕様を作り直します。インストーラが再起動を求める通常の更新では、そのあと起動し直すだけで足ります。

同じ WSL セッションを動かしたままドライバディレクトリだけ変わったときは、このサービスが `/usr/lib/wsl/drivers` を監視しないため、古いパスが残ります。仕様を作り直してから、もう一度起動します。

```bash
sudo systemctl start nvidia-cdi-refresh.service
docker compose up -d
```

Windows 側で `wsl --shutdown` してから WSL を開き直しても、同じ再生成が走ります。

## ワーカーが再起動を繰り返す

ログに「別のワーカーが稼働中です」と出る場合、別の worker コンテナがロックを持っています。プロジェクト内の worker は1つにしてください。前回のプロセスが落ちた直後は、ロック解放を最大30秒待ちます。

## 配信者がエラーのまま

TikTok の `is_live` がタイムアウトまたは例外になると `ERROR` です。これはオフラインではありません。監視は他の配信者を続けます。失敗した配信者だけ指数バックオフで間隔を空けます。

ツイキャスで `credentials_missing` または `auth_401` のときは Client ID / Secret を確認します。`user_not_found` は screen_id の誤りです。配信していないユーザーは `OFFLINE` です。

## 録画が始まらない

- 録画スイッチと全体の同時録画上限
- 空き容量が最低値を下回っていないか
- 合言葉、メンバーシップ、年齢制限。これらは別エンジンへ切り替えません
- Streamlink が「The stream is inaccessible」を返したとき。公開配信以外は失敗として記録し、回避のためのクッキー注入は行いません

エンジンの最終失敗理由は「システム」画面に出ます。抽出失敗のときだけ、設定した順序で次のエンジンを試します。データを受信したあとの切断は、同じエンジンで再接続し、欠損区間を残します。

## 録画開始の直後に失敗する

履歴で「録画を開始」の直後に `FAILED` になり、録画エラーが `runner crashed` のときは、保存先ディレクトリの所有者を確認します。イベントは「録画処理が異常終了しました」です。セグメントは作られません。

`RECORDINGS_DIR` と `CONFIG_DIR` がホスト上に無い状態で初めて起動すると、Docker は bind mount 用にそのディレクトリを root 所有で作ります。app と worker は `PUID` / `PGID` で動くため、セグメント用ディレクトリを作れず録画が落ちます。

所有者を `PUID`:`PGID` に一度合わせれば、再起動のたびに root へ戻ることはありません。パスは `.env` の値です。

```bash
sudo chown -R 1000:1000 /path/to/recordings /path/to/config
```

`1000:1000` は `.env` の `PUID` と `PGID` に置き換えます。もう一度必要になるのは、ディレクトリを消して Docker が作り直したときと、`PUID` や `PGID` を変えたときだけです。初回起動の前に、同じユーザーでディレクトリを作っておけばこの操作は不要です。

## コメントだけ失敗する

TikTok のコメントは Euler Stream への署名が必要です。`SIGN_API_KEY` が空でもライブラリは接続を試みますが、制限や失敗でコメントジョブが `FAILED` や `PARTIAL` になることがあります。録画ジョブは止まりません。

ツイキャスのコメントは movie ID が取れてから、最大50件ずつ、全体でおおよそ毎分50リクエスト以内に取得します。収集開始前のコメントは「欠損」として残すことがあります。

## ファイルが再生できない

履歴の検証が `invalid` または `partial` のファイルは、MP4 への詰め直しに失敗したか、途中で切れています。ダウンロードできる形式のまま残してあります。画面では再生しません。

## 容量

自動削除がオフのときはファイルを消しません。設定で有効にし、保存期限が1日以上のときだけ、期限を過ぎた確定ファイルを削除します。コメント期限を設定すると、期限を過ぎたコメントと自動書き出しの SRT を削除します。手動エクスポートは保存しません。

## ログに秘密が出る

`sign`、`token`、Bearer、URL はマスクします。それでも気になる値があればログレベルを `INFO` のままにし、`DEBUG` へ上げた状態を長時間残さないでください。
