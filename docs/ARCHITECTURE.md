# 構成

ブラウザは `app` だけに接続します。`worker` と `app` は PostgreSQL を共有し、録画ファイルは同じボリュームを見ます。Redis や Celery は使いません。

```text
Browser
  -> app (FastAPI / Jinja2 / HTMX)
       -> PostgreSQL
  worker
       -> PostgreSQL
       -> Recordings volume
       -> TikTok room API / CommentEvent
       -> Streamlink / yt-dlp / FFmpeg
       -> TwitCasting API v2
  transcriber
       -> PostgreSQL
       -> Recordings volume
       -> faster-whisper（CUDA）
```

ワーカーは PostgreSQL のアドバイザリロックを1つ保持し、コンテナを二重起動しても録画が重ならないようにします。プロセスが落ちるとロックは解放されます。

## ディレクトリ

- `src/live_recorder/platforms` — ユーザーIDの正規化、配信状態、コメント変換
- `src/live_recorder/recording` — 外部コマンド、ファイル名、確定、容量、照合
- `src/live_recorder/comments` — 重複排除、時刻オフセット、書き出し、統合 ASS
- `src/live_recorder/speech` — 文字起こし、SRT、単語ヒント
- `src/live_recorder/monitor` — 監視判断、録画ジョブ、コメントジョブ、復旧
- `src/live_recorder/web` — 認証付き管理画面
- `alembic` — スキーマ初期化

## 状態

録画は `PENDING → STARTING → RECORDING` です。切断後は `RECONNECTING` から新しいセグメントを開き、終了時は `FINALIZING` を経て `COMPLETED`、`PARTIAL`、`FAILED`、`CANCELLED` のいずれかになります。

コメントは `PENDING → CONNECTING → COLLECTING` です。切断は `RECONNECTING`、欠損があれば `PARTIAL`、設定オフは `DISABLED` です。

配信状態が取得できないときは `OFFLINE` にせず `ERROR` または `UNKNOWN` のままにします。その間、開いている配信は終了扱いしません。

## ワーカーの再起動

起動時に未完了の録画とコメントを拾います。中断区間の理由は `worker_restart` で、確定前のジョブは `RECONNECTING` に戻します。開いたままのセグメントはファイルがあれば確定し、ジョブ自体は終了しません。配信が続いていれば新しいセグメントを開きます。Windows の再起動もこの経路です。`docker compose stop` や `down` では、ワーカーが SIGTERM のあと最大 20 秒で録画を区切ります。

## 配信者一覧

デフォルトの並びはプラットフォーム名、表示名、登録順です。カスタムはドラッグした順を `sort_order` に保存し、追加した配信者は末尾に入ります。どちらの並びを画面に出すかは、ブラウザのセッションに残します。カスタムのときだけ、行をドラッグできます。

## 録画とコメントの分離

配信者ごとに録画タスクとコメントタスクを別々に起動します。片方が例外で終わっても、もう一方のタスクはキャンセルしません。合言葉配信とメンバーシップ配信は、公式レスポンスの `is_protected` / `is_membership` を見て両方とも開始しません。

## 保存

内部時刻は UTC です。画面、書き出し、ファイル名の日付は表示タイムゾーン（既定 `Asia/Tokyo`）です。プラットフォームが開始時刻を返さない場合、`platform_started_at` は NULL のままです。

ファイルは `{プラットフォーム}/{ユーザーID}/{日付}/` に置きます。日付は `YYYY-MM-DD` です。名前は `{プラットフォーム}_@{ユーザーID}_{年月日時分秒}_{タイトル}_seg01` で、時刻は `YYYYMMDD_HHMMSS` です。コメントの自動書き出しは同じ幹の `_Comments.srt`、音声字幕は `_Speech.srt`、統合字幕は `.ass` です。

録画はまず MPEG-TS に書き、ffprobe で確認してから `-c copy` で MP4 に詰め直します。詰め直しに失敗したファイルは、再生できる元の形式のまま残します。セグメントは結合しません。

画面の「録画範囲」は、セグメントを開いてから録画プロセスが終わるまでの壁時計です。「時間」は ffprobe が出した再生時間です。検証済みは、1 KiB を超えるファイルに映像か音声があり、ffprobe で容器を読めたことです。詰め直しに失敗しても、元のファイルがこの条件を満たせば検証済みのまま残します。壁時計と再生時間の差は見ていません。字幕の「発話なし」は、その再生時間を文字起こしして発話が残らなかった結果です。

`recording_offset_ms` は録画開始時刻が分かっているときだけ計算します。開始より前のコメントは負の値です。録画が始まっていなければ NULL です。

コメント字幕の1行は `本文 (名前 | @id)` です。id が無いときは `本文 (名前)`、名前が無いときは `本文 (@id)`、どちらも無いときは `本文 (unknown)` です。本文が空のときは括弧だけにします。

## 音声字幕

確定したセグメントを1本ずつ文字起こしします。配信中は処理しません。`transcriber` は NVIDIA GPU を使い、同時に走らせるのは1件です。結果は動画と同じ幹の `_Speech.srt` です。

生成時間は `speech_duration_ms` に残します。モデルの読み込みから文字起こしが終わるまでの壁時計で、統合字幕の作成は含めません。音声字幕の画面と録画詳細に出し、処理中は開始時刻からの経過を表示します。再生成で待ちに戻すと、前回の時間は消します。

前の区間の本文は次の区間の条件にしません。字幕の文章は Whisper のセグメントのままです。同じ音声をもう一度、語の時刻だけを読み、セグメントの内側に収まる塊で開始と終了を寄せます。1秒以上離れた語は使わず、塊が区間の外に出るときはセグメントの時刻を残します。

温度 0 で残った区間のうち、次は字幕にしません。圧縮率が 2.4 を超えるもの、平均対数確率が -1.0 未満のもの、記号だけの本文、無音で出る定型句そのもの、同じ節が3回以上続くもの、12文字以上で直前と同じ本文です。短い相づちは残します。

## 統合字幕

セグメントごとに、動画と同じ幹の `.ass` を作ります。MPC-HC は同じ名前の字幕を自動で読みます。音声とコメントは1つのトラックです。

音声は下中央、スタイル名は `Speech`、色は白です。コメントはそのすぐ上に段を重ね、スタイル名は `Comment`、色は黄です。書体名は空です。MPC-HC では字幕スタイルに `Speech` と `Comment` を追加し、書体・大きさ・色をそれぞれ指定します。

SRT は寄せた開始と終了です。次の音声字幕が 0.4 秒以内に続くときは、ASS もその終了まで出します。間が空くときだけ、1文字あたり 0.4 秒、最短 2.5 秒、最長 10 秒に切ります。絵文字は ASS の本文から除きます。

作り直すのは、コメントの自動書き出し、音声字幕の完了、録画詳細からの「統合 (ASS)」ダウンロードです。削除するときは、コメントの副ファイルと音声字幕に合わせて消します。

## 外部サービス

TikTok の配信有無は署名サービスを使いません。確認は1人ずつ、間隔は 1.5 秒です。空応答、壊れた JSON、HTTP 403、429、500番台のときは、TikTok の確認全体を 5 分止めます。きっかけになった1件はその理由のまま残り、休止に入ったあとの確認は API を呼ばず `http_403` になります。それ以外の失敗は、その配信者だけ指数バックオフします。上限は約 60 秒です。コメント受信と、第3手段の TikTokLive 録画は、ライブラリ既定の Euler Stream (`https://api.eulerstream.com`) へ署名要求を送ります。送るのはルーム解決に必要な識別子と User-Agent、設定している場合の API キーです。`sessionid` は送りません。CAPTCHA 解決 API は呼びません。

ツイキャスは公式 API です。Client ID と Client Secret の Basic 認証、または Bearer トークンを使います。パスワード配信の合言葉は渡しません。

## ツイキャスの録画

エンジン順は固定で、`official-hls` の次が `streamlink-hls` です。設定画面のエンジン順は TikTok だけを変えます。

`official-hls` は `streamserver.php` の `tc-hls` を画質設定で選びます。`best` と `high` は high、medium、low の順、`medium` は medium、low の順です。`twitcasting.tv` とそのサブドメイン以外の URL は捨てます。プレイリストが `#EXTM3U` で開いてからセグメントを作ります。合言葉配信と会員配信は作りません。

URI に `preroll-` が無いプレイリストは、FFmpeg が配信元を直接読みます。あるときは、プリロールのセグメントと、最初の本番セグメント直前の `#EXT-X-DISCONTINUITY` を除いたプレイリストを `127.0.0.1` で出し、約1秒ごとに更新します。相対 URL は配信元の絶対 URL にします。他ホストの URL は入れません。本番のセグメントが20秒現れるまでは FFmpeg を起動せず、現れなければその試行を失敗にします。マスタープレイリストなら、許可されたホストのうち帯域が最大のメディアプレイリストへ進みます。

FFmpeg はプレイヤーと同じ User-Agent と `Referer: https://twitcasting.tv/` を付け、`-c copy -f mpegts` で書きます。入力の読み取り待ちは30秒です。出力ファイルの大きさが45秒変わらないときはプロセスを止めます。この停止は監視オフや配信終了と区別し、再接続へ回します。標準エラーには `output stalled` を残します。

64 KiB 未満で中断した試行は次のエンジンへ切り替えます。それ以上書いてからの中断は、再接続回数まで同じエンジンです。0バイトの試行はセグメント行を残しません。Streamlink には `--stream-types hls` だけを渡し、低遅延の WebSocket（llfmp4）は使いません。詳細に保存するエンジン名は、最後にセグメントを開いたエンジンです。
